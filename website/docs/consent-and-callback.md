# Website consent and callback

The marketing website bundles MIT-licensed `vanilla-cookieconsent` 3.1.0 from npm. Its JavaScript and CSS are served with the website; no consent CDN/account is used. `consent-config.ts` and `consent-copy.ts` define necessary, callback and analytics categories for en/ro/de/es/fr/it, using the page footer's server-supplied locale and existing localized contact routes. The consent cookie is `360configurator_consent`, secure on HTTPS, SameSite=Lax, path `/`, 180 days, scoped to the current host. Choices are not copied between country domains.

Existing analytics-only decisions migrate once without enabling callbacks. The old `360-analytics-consent-v1` localStorage key remains a compatibility mirror for the unchanged standalone configurators. A migration marker prevents an expired/revised CookieConsent choice from being recreated from that mirror. Same-origin standalone analytics changes are reconciled while preserving callback permission. Standalone configurators retain their existing consent UI; only the marketing website changes here.

Analytics still uses the incumbent GA property, public-domain/staff checks and event payloads. CookieConsent is authoritative before analytics starts. Withdrawing statistics disables measurement and clears GA cookies without reloading or losing form state. No additional manual pageviews are introduced.

The compact blue callback launcher follows 360design's dimensions and styling: a labeled desktop button and 52 px mobile icon with a translated accessible name. It opens CookieConsent preferences when callback permission is absent; the vendor script loads only after permission and an explicit callback request. On a load failure it offers the existing public phone number. The provider's own launcher is hidden; its native popup and click handler are retained. Disabling an already-loaded callback service reloads the page to stop vendor sockets/timers, matching 360design; this consequence is explained in each language. No reload occurs for an unstarted callback service or analytics-only withdrawal.

SwiftCallback's current script accepts native `lang=ro/en/ru`. For German, Spanish, French and Italian, `swift-callback-locales.ts` supplies its existing global translation dictionary before mount, including scheduling labels/month names. This adapter depends on the vendor's current `swiftCallbackTranslations` assignment and native `.swift-widget-button` target. Recheck both if the vendor changes its script. It does not replace the vendor's call submission backend or make test calls.

Run `npm run test:consent`, then the production build/export and `test:postlaunch`. Browser verification should cover first visit, refusal, selective categories, migration, expiry, reopening, callback loading/failure, withdrawal, independent domains, both themes and narrow translated layouts. Optional service network calls must remain absent before permission. Callback opening is intent, not a delivered lead.
