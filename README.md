# Configurator 360

Browser-based Schüco window configurator with desktop GLB/USDZ generation, Netlify upload tickets, Supabase Storage, Android Scene Viewer, and Apple AR Quick Look.

## Project layout

```text
src/
  client/                  Browser configurator and public assets
  server/                  Local Node/Playwright server
cad/
  source/                  DWG/DXF source files
  intermediate/            Conversion output and temporary CAD files
  tools/                   DWG/DXF/SVG conversion utilities
scripts/
  build/                   Static-site build script
  windows/                 Double-click Windows helpers
  migrations/              One-time historical migration tools
netlify/
  functions/               Netlify Functions
  _headers                  Headers copied into the static build
infrastructure/
  cloudflare-worker/        Legacy/alternative Cloudflare Worker deployment
docs/                       Active documentation and archived implementation notes
runtime/generated/          Local generated AR models; ignored except for .gitkeep
dist/site/                  Generated deployable site; never edit directly
```

The browser source lives only in `src/client`. `dist/site` is generated by the build and is intentionally not committed. This removes the previous duplicate `static-site` copy.

## Common commands

```powershell
npm install
npm start
npm run check
npm run prepare:static
npm run deploy:netlify
```

Windows helper scripts are under `scripts/windows/`:

- `start_local_site.vbs`
- `prepare_static_site.vbs`
- `deploy_netlify_with_functions.cmd`

## AR publication flow

```text
Android selected -> optimized GLB -> Supabase -> Scene Viewer
iOS selected     -> optimized USDZ -> Supabase -> AR Quick Look
```

Only the selected representation is generated and uploaded for each QR publication. Existing publications remain valid when another platform is selected.

Setup details are in [`docs/deployment/SUPABASE_NETLIFY_SETUP.md`](docs/deployment/SUPABASE_NETLIFY_SETUP.md).
